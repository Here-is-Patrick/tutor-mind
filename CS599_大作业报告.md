## 一、选题背景与设计思想

### 1.1 问题定义

传统在线教育平台（如 MOOC、题库系统）普遍存在以下痛点：

1. **缺乏个性化**：所有学生看到相同的教学内容，无法根据学生基础水平调整难度
2. **单向灌输**：以视频讲解和文字答案为主，学生被动接受，缺乏主动思考
3. **无记忆连续性**：每次提问都是独立事件，系统不记得学生之前问过什么、学过什么
4. **即时性问题**：知识库更新滞后，无法回答最新领域问题
5. **基础差异被忽略**：基础薄弱的学生容易被专业术语劝退，而基础好的学生又觉得内容太简单

### 1.2 现有方案不足

| 方案类型 | 代表产品 | 不足 |
|----------|----------|------|
| 传统题库 | 猿题库、作业帮 | 只给答案，不引导思考；无对话能力 |
| 视频课程 | 中国大学 MOOC | 单向灌输，无法交互；无法根据学生反馈调整 |
| 通用大模型 | ChatGPT、文心一言 | 无学生画像，回答风格固定；无知识库优先检索 |
| 智能客服 | 企业 FAQ 机器人 | 只能回答预设问题，无苏格拉底引导能力 |

### 1.3 项目价值

TutorMind 旨在构建一个**具备记忆、有个性、会引导、能搜索**的一对一智能辅导系统：

- **记忆**：短期记忆（当前会话上下文）+ 长期记忆（SQLite 持久化）+ 向量记忆（ChromaDB）三层记忆体系
- **个性**：根据学生基础水平（薄弱/正常）自适应调整回答风格和苏格拉底提问步长
- **引导**：采用苏格拉底教学法，通过递进式提问引导学生自行推导答案，而非直接给答案
- **搜索**：知识库优先检索 + Tavily 实时搜索兜底，确保回答的准确性和时效性
- **多轮对话**：基于 LangChain BaseMessage 标准消息序列，LLM 原生理解对话上下文

### 1.4 技术路线

```
学生输入
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  LangGraph StateGraph 状态机编排                             │
```

## 二、Specs 规格文档

### 2.1 Product Spec（产品规格）

**目标用户**：K12 及大学阶段需要个性化辅导的学生

**核心用户故事**：

1. 作为学生，我希望系统记住我的名字和基础水平，这样每次对话都不需要重复介绍自己
2. 作为基础薄弱的学生，我希望系统用通俗易懂的语言和类比解释概念，避免被专业术语劝退
3. 作为学生，我希望系统通过提问引导我思考，而不是直接给答案，这样我能真正理解
4. 作为学生，我希望系统能记住我之前问过的问题，在后续对话中参考
5. 作为学生，我希望系统能回答最新的、知识库中没有的问题

### 4.1 Agent 核心循环

**LangGraph 工作流定义**（workflow.py）：

```python
def build_workflow() -> StateGraph:
    workflow = StateGraph(TutorState)

    # Add nodes
    workflow.add_node("check_student_info", check_student_info)
    workflow.add_node("collect_info", collect_info)
    workflow.add_node("search_knowledge_base", search_knowledge_base)
    workflow.add_node("socratic_teach", socratic_teach)
    workflow.add_node("tavily_search", tavily_search)
    workflow.add_node("generate_answer", generate_answer)

    # Set entry point
    workflow.set_entry_point("check_student_info")

    # Conditional edges
    workflow.add_conditional_edges(
        "check_student_info",
        route_after_check,
        {"collect_info": "collect_info", "search_knowledge_base": "search_knowledge_base"},
    )
    workflow.add_conditional_edges(
        "collect_info",
        route_after_collect,
        {"__end__": END, "search_knowledge_base": "search_knowledge_base"},
    )
    workflow.add_conditional_edges(
        "search_knowledge_base",
        route_after_kb_search,
        {"socratic_teach": "socratic_teach", "tavily_search": "tavily_search"},
    )

    # Direct edges
    workflow.add_edge("socratic_teach", END)
    workflow.add_edge("tavily_search", "generate_answer")
    workflow.add_edge("generate_answer", END)

    return workflow

def create_tutor_graph() -> StateGraph:
    workflow = build_workflow()
    memory = MemorySaver()
    return workflow.compile(checkpointer=memory)
```

### 4.3 记忆机制实现

**三层记忆体系**：

```python
# 1. 短期记忆 — 内存滑动窗口
class ShortTermMemory:
    def __init__(self):
        self._store: dict[str, list[dict]] = {}

    def add(self, session_id: str, role: str, content: str):
        self._store.setdefault(session_id, []).append({"role": role, "content": content})
        # 滑动窗口：只保留最近 N 条
        self._store[session_id] = self._store[session_id][-self.max_messages:]

# 2. 长期记忆 — SQLite 持久化
class LongTermMemory:
    def save_message(self, student_id, session_id, role, content, agent_name=None):
        with get_db() as db:
            db.execute(
                "INSERT INTO messages (student_id, session_id, role, content, agent_name) VALUES (?, ?, ?, ?, ?)",
                (student_id, session_id, role, content, agent_name),
            )
            db.commit()

# 3. 向量记忆 — ChromaDB
class VectorStore:
    def add_qa(self, qa_id, question, answer, embedding, metadata):
        self.collection.add(
            ids=[qa_id],
            embeddings=[embedding],
            documents=[f"Q: {question}\nA: {answer}"],
            metadatas=[meta],
        )
```

```python
def get_adaptive_instructions(student_id: str) -> str:
    profile = get_student_profile(student_id)
    if profile and profile.is_weak_foundation:

    return ADAPTIVE_INSTRUCTIONS["normal"]
```

### 4.5 RAG 检索实现

```python
class KnowledgeRetriever:
    def retrieve(self, question: str, top_k: int | None = None, student_id: str | None = None):
        query_embedding = self.embeddings.embed_query(question)
        all_matches = self.vector_store.search_similar(query_embedding, top_k)

        # 相似度阈值过滤
        qualified = [m for m in all_matches if m["similarity_score"] >= self.threshold]

        # 学生隔离：只返回当前学生的记录
        if student_id is not None:
            qualified = [
                m for m in qualified
                if m.get("metadata", {}).get("student_id") == student_id
            ]

        best = qualified[0] if qualified else None
        return {"found": len(qualified) > 0, "similar_questions": qualified, "best_match": best}
```

## 七、课程总结

### 7.1 个人收获

通过 CS599 课程的学习和 TutorMind 项目的开发，我在以下方面获得了显著提升：

1. **从"代码编写者"到"智能体编排者"的思维转变**
   - 传统编程是写死逻辑（if/else），而 Agent 开发是设计角色、定义状态、编排流程
   - 学会了用 LangGraph 的 StateGraph 将复杂业务逻辑拆解为可组合的状态节点

2. **SDD 规格驱动开发的实践**
   - 先写 Product Spec 明确用户故事，再写 Architecture Spec 设计架构，最后写 API Spec 定义接口
   - 规格文档成为代码的"蓝图"，开发效率显著提升，返工率降低

3. **多智能体协作的设计能力**
   - 五个 Agent 各有职责，通过共享 TutorState 协作
   - 学会了设计条件路由（Conditional Edges）处理分支逻辑

4. **记忆机制的工程实现**
   - 理解了短期记忆、长期记忆、向量记忆的分层设计
   - 掌握了 LangGraph MemorySaver 的 Checkpoint 机制

5. **多轮对话的实现原理**
   - 从"把历史拼成字符串"到"用 BaseMessage 列表传递标准消息序列"
   - 理解了 LLM 原生多轮对话的优势（角色清晰、上下文利用率高）

### 7.2 工程思维转变

| 传统开发思维 | Agent 开发思维 |
|-------------|---------------|
| 写死业务逻辑 | 设计角色和状态机 |
| 单元测试覆盖代码 | 评估 Agent 行为是否符合预期 |
| 错误处理用 try/catch | 设计降级策略（搜索兜底） |
| 数据库查一条记录 | 向量数据库语义检索 |
| 用户输入直接处理 | 先识别意图，再路由到对应 Agent |

### 7.3 对课程的建议

1. **增加 MCP 协议的实战环节**：MCP 是 Agent 生态的重要协议，建议增加一个课时专门讲解和动手实践
2. **提供 LangSmith 免费额度**：LLMOps 可观测性需要实际接入追踪平台，建议协调厂商提供免费学生额度
3. **增加多模态 Agent 的案例**：当前案例以文本为主，建议补充语音/图像 Agent 的开发案例
4. **分组协作项目**：Agent 系统复杂度较高，建议 2-3 人一组协作开发，体验多智能体协作的同时锻炼团队协作能力
